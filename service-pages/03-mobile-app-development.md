### Native or cross-platform?

A real decision, not a preference — and one worth answering on the page, because buyers arrive
already asking it:

- **Native (Swift / Kotlin)** when you need platform-specific depth: heavy device APIs, demanding
  performance, or close platform integration.
- **Cross-platform (React Native / Flutter)** when the feature set is shared across both platforms
  and one codebase is the cheaper, faster route.

See [Flutter vs React Native](/blog/flutter-vs-react-native) and
[Shipping mobile on two platforms](/blog/shipping-mobile-on-two-platforms).

## What drives cost

- **Native or cross-platform**, and whether both platforms are in scope
- **Feature depth** — offline sync, payments and background work each carry real weight
- **Backend state** — an existing API to build against, or one to be built
- **Design state** — designs ready, or design work in scope
- **Compliance** — regulated-sector requirements for data handling on device
- **Store and release management** — one submission, or an ongoing release cadence

## FAQ

**Do you build mobile apps for iOS and Android?**
We do. We take a mobile product from written specification to a signed build in both stores, native
in Swift and Kotlin or cross-platform with React Native or Flutter. Every app is laid out properly
for tablets rather than stretched, with offline-first data, push, deep links, and in-app payments
where needed.

**Should we go native or cross-platform?**
Native when you need platform depth — heavy device APIs or demanding performance. Cross-platform
when the feature set is shared and one codebase is the faster, cheaper route. We make the
recommendation against your actual feature list, not a house preference.

**Can you take over an existing app?**
Yes. An advisory and architecture review establishes what is there and what it would take to move
it forward, before any rewrite is considered.

**Do you handle App Store and Play Store submission?**
Yes — signed builds, store listings, review handling and release management. Store review times
themselves sit with Apple and Google.

**Do we own the code and signing assets?**
Completely, including documentation, with handover designed in from the start.
